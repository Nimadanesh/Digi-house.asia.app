# DigiHouse i18n guide

Multi-language support uses **`next-intl`** (client provider, no locale URL prefix — Telegram Mini Apps keep stable deep links).

## Supported locales

| Code | Language | Direction |
|------|----------|-----------|
| `en` | English (default / source of truth) | LTR |
| `fa` | Persian (Farsi) | RTL |
| `ar` | Arabic | RTL |
| `ru` | Russian | LTR |
| `de` | German | LTR |
| `tr` | Turkish | LTR |

## Layout

```
messages/
  en.json   # source of truth
  fa.json
  ar.json
  ru.json
  de.json
  tr.json
src/i18n/
  config.ts          # LOCALES, RTL_LOCALES, LOCALE_META
  detect-locale.ts   # Telegram language_code → AppLocale
  get-messages.ts    # dynamic import of catalogs
src/components/i18n/
  LocaleProvider.tsx # NextIntlClientProvider + dir/lang on <html>
src/components/settings/
  LanguageSelector.tsx
```

## How locale is chosen

1. **Persisted preference** — `useSettingsStore().locale` (`null` = Auto).
2. **Telegram** — `initDataUnsafe.user.language_code` (via SDK `initDataUser`).
3. **Browser** — `navigator.language` (dev outside TMA).
4. Fallback: **`en`**.

Preference is stored in `localStorage` under `digihouse-settings`.

## Using translations in UI

```tsx
"use client";
import { useTranslations } from "next-intl";

export function Example() {
  const t = useTranslations("home");
  return <h1>{t("portfolioValue")}</h1>;
}
```

Namespaces: `common`, `tabs`, `header`, `onboarding`, `home`, `marketplace`, `property`, `earnings`, `portfolio`, `settings`.

Interpolation: `t("myPropertiesCount", { count: 3 })` → keys use `{count}` in JSON.

## RTL

- `LocaleProvider` sets `document.documentElement.dir` to `rtl` for `fa` / `ar`.
- Prefer **logical** Tailwind utilities: `start`/`end`, `ps`/`pe`, `ms`/`me`, `text-start`/`text-end` (not `left`/`right`).
- Mirror chevrons with `rtl:rotate-180`.
- Onboarding carousel flips swipe direction in RTL.

## Adding a new language

1. Add the code to `LOCALES` and `LOCALE_META` in `src/i18n/config.ts`.
2. If RTL, add it to `RTL_LOCALES`.
3. Copy `messages/en.json` → `messages/<code>.json` and translate values (keep keys identical).
4. Register the loader in `src/i18n/get-messages.ts`.
5. Extend `detectLocaleFromCode` if Telegram uses a non-obvious primary subtag.
6. Run `npm run check` and spot-check Settings → Language + one RTL screen if applicable.

## Rules

- **English is the source of truth** — never invent English copy only in another file.
- Keep keys **namespaced** and stable (`onboarding.own.headline`, not free-form strings).
- Do not put locale segments in routes (`/fa/home`) — TMA start URLs stay fixed.
- Property titles/locations from seed data stay in their source language until a content CMS exists.
- MVP payout honesty copy must stay accurate in every language (simulated / post-MVP).
