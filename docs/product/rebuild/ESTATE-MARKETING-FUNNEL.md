# FractionalLuxe — Estate Marketing Funnel

Status: PRODUCT CONTRACT
Scope: Estate / Income / Ownership / Detail tabs

---

## 1. Product Principle

The four Estate tabs are NOT four versions of the same property page.

They represent four different stages of the user's mental journey:

1. ESTATE → Desire
2. INCOME → Conviction
3. OWNERSHIP → Decision
4. DETAIL → Information / Truth

The first three tabs are investment-conversion surfaces.

The Detail tab is an information/reference surface and must NOT be optimized for persuasion.

---

# 2. Funnel

Property discovery
      ↓
ESTATE
"Why should I care about this asset?"
      ↓
INCOME
"Does the economics make sense?"
      ↓
OWNERSHIP
"Can / should I become an owner?"
      ↓
BUY
"How much do I want to invest?"
      
DETAIL is orthogonal:

DETAIL
"What exactly is this property?"

The user may enter Detail at any point.

---

# 3. TAB 1 — ESTATE

## Objective

Create desire and initial investment interest.

The user should leave thinking:

> "This is an interesting asset. I want to understand the economics."

## Primary question

"Why is this Estate worth considering?"

## UX role

ESTATE is the investment story.

It should combine:

- property identity
- visual appeal
- investment opportunity
- ownership framing
- high-level economic narrative
- clear next action

## Information priority

1. Property identity
2. Emotional / visual story
3. Why the asset is interesting
4. How the asset makes money
5. What fractional ownership means
6. Genuine availability / funding state
7. Investment CTA

## Do NOT overload this tab with

- complete amenities
- every house rule
- complete service list
- every tax detail
- full source description
- exhaustive physical specifications

Those belong in Detail.

## Conversion principle

The tab should move:

Interest → Understanding → Curiosity → Investment intent

Never use:

- fake scarcity
- fake urgency
- fake investor counts
- fake earnings
- fake timers
- fake activity
- invented market prices

---

# 4. TAB 2 — INCOME

## Objective

Strengthen investment conviction through economic understanding.

The user should leave thinking:

> "I understand how this asset generates income and what that means for ownership."

## Primary question

"How does this Estate make money?"

## Economic storytelling

Property
→ Rental / Operating Revenue
→ Operating Costs
→ Net Economics
→ Ownership
→ Investor Income

Every number must come from the canonical economic engine or explicitly identified source.

## Information priority

1. Revenue mechanism
2. Rental performance
3. Cost structure
4. Net economics
5. Investor share
6. Projected / accrued / paid distinction
7. Distribution status
8. Assumptions and provenance

## Critical rule

Never mix:

- Projected
- Accrued
- Eligible
- Requested
- Scheduled
- Paid

These are separate economic states.

## Missing data

If economics are unavailable:

Show the known state honestly.

Example:

"Occupancy data pending"

is valid.

A fabricated occupancy percentage is not.

---

# 5. TAB 3 — OWNERSHIP

## Objective

Convert investment interest into an ownership decision.

The user should leave thinking:

> "I understand what owning a fraction of this Estate means, and I know what I can do next."

## Primary question

"What does ownership look like?"

## Information priority

1. Ownership structure
2. Total shares
3. Available shares
4. Funded / remaining state
5. Existing ownership
6. User position
7. Primary / secondary market state
8. Purchase action

## Social proof rule

Existing holders may be shown only when the data is real and product-approved.

Never fabricate:

- investor counts
- recent activity
- buyers
- transaction volume
- demand
- popularity

## Ownership language

Ownership must remain clear and literal.

Avoid language that implies:

- guaranteed returns
- guaranteed appreciation
- instant liquidity
- guaranteed buyers
- guaranteed income

# 6. TAB 4 — DETAIL

## Objective

Provide complete, trustworthy property information.

This tab is NOT a conversion surface.

The user should leave thinking:

> "I know what this property actually is."

## Primary question

"What are the facts about this property?"

## Detail should contain all available property information that is useful to a prospective owner / guest / evaluator.

### Identity

- Full property name
- Property type
- Location
- Country
- Region
- Place
- Source listing ID
- Source URL

### Physical specifications

- Guests
- Bedrooms
- Bathrooms
- Interior area
- Total area
- Pool area
- Land area
- Land notes

### Description

- Short description
- Full description
- Seasonality

### Amenities

- General
- Outdoor
- Indoor
- Kitchen
- Entertainment
- Activities
- Nearby

### Services

- Included services
- Staff
- Extra-cost services

### Rates

- Nightly display
- Currency
- Rate type
- Observed period
- Rate notes

### Taxes and fees

- Tourism tax
- Service charge
- Green tax
- Damage waiver
- Other observed fees

### Valuation

- Estimated value
- Value range
- Provenance
- Confidence

### Source / Trust

- Rental Escapes source
- Listing ID
- Research date
- Research confidence
- Provenance

## Detail principles

Do not hide relevant facts because they reduce conversion.

Do not exaggerate attractive facts.

Do not rewrite source facts into marketing claims.

Do not invent missing values.

Unknown is a valid state.

---

# 7. Cross-tab Rules

## Single source of truth

All four tabs must ultimately consume the same canonical Estate record.

They may present different subsets and interpretations.

They must never maintain competing versions of:

- name
- location
- images
- nightly rate
- property type
- size
- valuation
- description

## Marketing vs Information

ESTATE / INCOME / OWNERSHIP:

Purposeful selection and sequencing of information is allowed.

DETAIL:

Completeness and accuracy take priority over persuasion.

## Provenance

Every uncertain or estimated financial/property fact must have appropriate provenance.

Use the existing compact provenance UI.

Do not expose internal provenance vocabulary as visual clutter unless required.

## Missing data

Never convert UNKNOWN into:

- zero
- estimated value
- synthetic value
- placeholder-looking factual value

unless the business contract explicitly allows it.
